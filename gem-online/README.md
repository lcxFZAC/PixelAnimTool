# Gemini Gem 在线方案 · 新手指南

这里包含两个相互配合的交付：**Gem 对话配置包**和**在线工坊部署配置**。都可以在线使用，不要求最终使用者运行本地工坊。

Gem 官方允许创建自定义指令并上传知识文件；本包按这个真实能力制作，并非声称存在一个可安装任意代码、自动调用我们服务器的 Gem 插件接口。[官方 Gem 创建说明](https://support.google.com/gemini/answer/15235603?hl=en)

## 方式一：在 Gemini 官网使用 Gem

1. 登录 [Gemini 官网](https://gemini.google.com/)，进入 **探索 Gems / Explore Gems**，选择 **新建 Gem / New Gem**。界面名称随账号语言与版本可能不同。
2. 名称填写 **像素工坊 · 角色动作导演**。
3. 用记事本打开 [`GEM-INSTRUCTIONS.txt`](GEM-INSTRUCTIONS.txt)，全选复制到 Gem 的“指令”框。
4. 在知识/文件区域上传 [`PIXEL-STANDARD.txt`](PIXEL-STANDARD.txt)。如你有已认可的角色母版，可以在实际对话里附上。
5. 保存。右侧预览并不等于已保存，必须完成保存操作。
6. 打开该 Gem 的新对话，上传一张全身正面立绘，输入 **“待机”** 或 **“行走”**。先检查一个动作，再继续整包。

可以直接输入：

```text
移动
```

或者：

```text
行走，向右，风格=玖镇，画布=96x128，PPU=48，腰间铜钱保持角色自身左侧。
```

返修示例：

```text
第3帧手腕断开，沿用已认可的角色母版，修正连接并保持其他身份特征。
```

默认移动包含四向待机和四向行走；战斗包含向右待机、普攻、施法、受击、倒地。Gem 一次做一个动作/方向，受当前会话实际生图次数限制时明确列出剩余项，输入“继续”接着做，不能把一张图说成整包完成。

**能力不足时**：如果你的Gem会话没有实际生图工具，它应说明缺少能力，只输出规格，不能假装已生成。此时可以把同样的图和要求交给支持图像生成的Gemini入口，或使用下方在线工坊的API模式。

**对话稳定性**：同一对话固定规格与方向母版；跨对话重新附上母版和制作记录。指令能约束流程，但不是数学上的成功率保证。仍需视觉检查和返修。纯Gem模式不能保证精确PNG透明通道、原生像素格、ZIP和切片JSON，须经工坊处理。

## 方式二：部署在线工坊，浏览器完成全流程

在线工坊与本地工坊使用同一份引擎，避免两端规则漂移。源码在相邻 `local-workshop/`，Docker从仓库根目录构建，但运行后**不依赖你的本机服务、Unity或本机目录**。

你需要自己的云托管账号。仓库当前没有已发布的在线地址；这里交付的是可部署代码，没有代替你创建账号、购买托管或伪造已上线状态。

### 使用 Render 图形界面部署

1. 将整个 `PixelAnimTool` 仓库上传到你自己的 GitHub/GitLab 仓库。保留两个目录；不要只上传 `gem-online`。`data/`、`.venv/`、Key和日志已在忽略列表，勿强制加入。
2. 登录 [Render](https://render.com/)，选择 **New → Blueprint**，连接该仓库。
3. 在 **Blueprint Path** 中填写 `gem-online/render.yaml`。配置使用Docker构建，挂载 `/data` 持久化磁盘，并生成 `WORKSHOP_ACCESS_TOKEN`。持久磁盘和所选服务规格可能收费；在平台页面核对后自行决定部署。
4. 部署完成后，从服务 **Environment** 中查看生成的 `WORKSHOP_ACCESS_TOKEN`。这是你的工坊口令，不是Gemini Key。保持个人使用，不公开口令。
5. 打开Render给出的HTTPS服务地址，在页面输入工坊口令。
6. 上传角色，打开Gemini开关，输入自己的API Key，即可一张图＋一句要求调用生成、处理、编辑和导出。Key仍不持久保存；部署者不要在云环境变量中设置Gemini Key。
7. 后续从任意支持WebGL的电脑浏览器访问这个网址即可，本机不需要启动Python。及时下载ZIP备份；磁盘和云账号归你管理。

此配置依据 [Render Docker 文档](https://render.com/docs/docker)、[Blueprint 字段说明](https://render.com/docs/blueprint-spec) 和 [自定义 Blueprint 路径说明](https://render.com/docs/infrastructure-as-code)。云平台发布流程和账单以当时页面为准。

### 已有 Docker 托管平台

从 **PixelAnimTool 仓库根目录** 构建：

```sh
docker build -f gem-online/Dockerfile -t pixel-workshop-online .
```

运行要求：容器端口默认10000（可通过PORT设置）；必须设置至少16字符的 `WORKSHOP_ACCESS_TOKEN`；持久卷挂载 `/data`；由托管平台提供HTTPS反向代理；健康检查为 `/health`。缺少口令时服务拒绝启动。

这是**个人单用户工坊**。所有持有同一个口令的人共享项目空间，不适合公开多用户服务；当前没有账号隔离、配额分账或多副本任务调度。使用单实例，升级/重启前等生成结束。后台中断时保留已完成动作，下次重新提交只补缺失项。

## Gem 与在线工坊如何配合

- **纯 Gem 生图**：官网对话生成实际原稿 → 下载图稿 → 打开你部署的在线工坊 → 上传图集、设置网格 → 检查/修图/导出。此流程全在线，但转交图片是手动操作。
- **真正的一键处理链**：直接在在线工坊上传立绘、输入要求并使用Gemini API。由后台依次调用模型、切片、检查和保存。
- 可以把自己部署的真实工坊网址追加到Gem指令，方便每次打开；这只是链接指引，不会凭空赋予Gem自动调用后台的能力。

默认4帧使用2×2网格，6帧使用3×2，8帧使用4×2；Gem图稿建议纯洋红背景，导入时选“移除边缘连通洋红”。不能整除网格时先修正边距；不要把裁断手脚的结果验收通过。

## 当前验证边界

Gem包已与引擎默认规格、动作数量和帧率对齐。在线模式的访问口令、API拒绝未授权访问等已在本机回归检查中覆盖。尚未在你的Gemini账号中安装、真实付费生图或云托管环境中部署；这些需要对应账号及Key，代码和文件本身不能代替这些权限。

任何“100%稳定、所有风格、任意立绘一次完美”的承诺都不真实。本方案实现的是固定配方、方向母版、工程处理、候选检查、返修和验收记录；实际角色质量需要用你的真实样本与账号模型验证。

## Pixel Art Fixer 与立体像素

在线部署共用本地工坊的 Pixel Art Fixer、八方旅人方向预设、HD2D 法线与修复对照面板；Docker 已包含 NumPy/SciPy/OpenCV headless 及固定版本 MIT 源码。更新 Gem 时重新上传 `PIXEL-STANDARD.txt`。单独的 Gem 对话只生成候选图稿，无法代替工坊实际执行修复和法线导出。云端处理最多 400 万像素，耗时/内存取决于部署规格；并发修复被限制为一个，180 秒超时保留原稿。
